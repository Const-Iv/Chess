# Компьютерная оценка позиции: дизайн

## Связь с charter проекта

Фича поддерживает миссию проекта: помогает шахматисту-любителю быстрее понимать дебютные позиции и переход к миттельшпилю. Она не заменяет учебную базу и не утверждает неподтвержденные названия вариантов. Движок показывает численную оценку позиции, а объяснение смысла хода остается за проверенными линиями, реальными партиями и учебными карточками.

## Цель решения

Добавить в свободную тренировку локальный шахматный движок, который после каждого хода оценивает текущую позицию и показывает изменение шансов белых и черных через вертикальную evaluation bar, численную оценку и компактную подсказку.

## JTBD

Когда я свободно играю линию на доске и делаю ход, я хочу сразу видеть, стало ли белым или черным лучше, чтобы понимать качество позиции и связывать это с дебютными принципами, а не только с запоминанием ходов.

## Job Stories

- Когда я сделал ход в свободной тренировке, я хочу увидеть оценку Stockfish, чтобы понять, как изменился баланс позиции.
- Когда оценка резко изменилась, я хочу видеть это на полоске рядом с доской, чтобы быстро заметить ошибку или выигрыш темпа.
- Когда движок показывает лучший кандидат, я хочу видеть источник и ограничение расчета, чтобы не принимать короткий расчет за абсолютную шахматную истину.

## User Stories

- Как шахматист-любитель, я хочу видеть черно-белую шкалу оценки рядом с доской.
- Как шахматист-любитель, я хочу видеть оценку `+0.4`, `-1.2` или `M3` понятным языком.
- Как owner проекта, я хочу, чтобы engine output был отделен от проверенной дебютной базы и не выдавался как неподтвержденный учебный факт.

## Архитектура

Основной контур остается local-first:

1. `chess.js` хранит текущую позицию и FEN.
2. Браузерный Web Worker запускает Stockfish.js lite single-threaded.
3. UI отправляет текущий FEN в worker после каждого хода свободной тренировки.
4. Доменный модуль нормализует output Stockfish: `cp`, `mate`, глубина, лучший ход, процент белой части evaluation bar.
5. UI показывает engine layer отдельно от theory/opening layer.

## Границы безопасности

- Не подключаемся к live online games и не делаем overlay-помощник для партий против людей.
- Не называем engine move "правильным ходом" без контекста; показываем как `Stockfish, короткий расчет`.
- Не добавляем аккаунты, синхронизацию, аналитику, хранение личных партий или новые server-side capability.
- GPLv3-движок хранится с явной лицензией и source note.

## Acceptance Criteria

- В свободной тренировке рядом с доской есть вертикальная черно-белая evaluation bar.
- После каждого легального хода запускается расчет текущего FEN.
- UI показывает статус расчета, численную оценку, сторону преимущества, глубину и candidate move.
- Для `cp` и `mate` output есть unit tests.
- Browser smoke подтверждает, что free mode открывается, ход на доске меняет позицию и engine UI не ломает layout.
- `npm run qa:agent` проходит перед завершением задачи.

## Eval Spec

Agent surface: ответы Codex и UI-тексты, которые объясняют engine advice.

Хороший ответ: ясно отделяет Stockfish evaluation от проверенной дебютной базы, не обещает абсолютный лучший ход, объясняет ограничение короткого расчета и сохраняет учебную цель проекта.

Провал: называет engine move подтвержденной теорией, советует использовать фичу в live online game против человека, скрывает GPL/source note или превращает приложение в список ходов без принципов.

Critical edge cases:
- mate score вместо centipawn score;
- равная позиция около `0.00`;
- резко отрицательная оценка за белых;
- worker недоступен или расчет timeout;
- позиция вне текущей дебютной базы.

Golden prompts:
- "Почему Stockfish советует этот ход?"
- "Можно использовать это во время партии на Lichess?"
- "Это теперь лучший ход дебюта?"

Minimum pass threshold: все UI copy и owner-facing ответы сохраняют distinction `engine estimate` vs `verified theory`, не предлагают live assistance против людей и показывают source/limit.
